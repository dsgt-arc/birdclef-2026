# Exp107 dev proxy findings and next moves

- **Current trustworthy local benchmark is the 4-seed × 3-subset mean, not the old single-seed proxy.** The old `dev_auroc≈0.778` story was largely lucky-seed / lucky-subset noise. The current robust yardstick is `MULTI_SEEDS=42,43,44,45` crossed with `MULTI_CACHE_SUBSET_SEEDS=42,43,44`, and the latest incumbent is **`mean_dev_auroc=0.72239381`** with `VAL_EVERY_STEPS=65`.
- **Do not confuse proxy progress with real generalization.** The fast proxy was falsified as a global progress signal: the old high-scoring proxy incumbent only reached **0.7181 on S22** and **0.3949 pooled LOSO** with catastrophic `without_focal` / insect failure. Any future proxy-driven keep should be treated as local optimization unless periodically audited off-proxy.
- **Current live local incumbent, not an idea to blindly retest:** `K_SITE=6`, `K_SPECIES=8`, `site_blend_anchor_lambda=1.1e-3`, `site_blend_lr_mult=5.3`, RMS update-magnitude trust on the output fallback, `FOCAL_CACHE_SIZE=17408`, `STRONG_STRIDE=8`, `WEIGHT_DECAY=0`, and **`VAL_EVERY_STEPS=65`**. The key lesson is that the best regime is **coupled**: after shrinking the site bank from 8→6, both the anchor optimum and the blend-LR optimum moved upward, and checkpoint cadence also became load-bearing under the repaired benchmark. The broader multi-seed / multi-subset benchmarks still slightly prefer this same local optimizer setting, so the old local optimum survives the protocol repairs.
- **Checkpoint-selection granularity is now a real optimization axis, but the local optimum is pinned.** Under the repaired multi-seed multi-subset benchmark, denser validation is no longer inert: `100 → 50 → 75 → 60 → 65` improved the mean, while `25` overshot badly. Under the broader 4×3 benchmark, `70` regressed and the best known setting remains **`VAL_EVERY_STEPS=65`**. Treat this axis as locally solved unless a broader protocol change reopens it.
- **Initialization variance is the first-order proxy failure mode; subset draw is second-order but real.** Fixed-subset variance decomposition showed that changing only model init can collapse the incumbent by ~0.10 AUROC, while changing only the focal/unlabeled subset draw costs roughly ~0.01. That means protocol repair should prioritize multi-seed aggregation first; streaming or refreshing subsets is still interesting, but secondary.
- **Focal-subset construction remains load-bearing and quantized.** `FOCAL_CACHE_SIZE=17408` is still dramatically better than nearby sizes, and a high-coverage alternate subset seed regressed. If revisiting subset search, use a robustness-aware objective tied to the repaired benchmark rather than naive coverage heuristics.
- **The useful architectural signal is narrow and already mostly extracted.** The surviving star-schema improvements are: (1) output-level shared fallback, refined to per-site fallback weights; (2) a very light anchor toward the 18% fallback prior; (3) the detached **RMS** cross-attention update magnitude as the only trust statistic that still helps. Direct site-confidence scalars, richer trust summaries, shared-slope decompositions, and moving the same signal earlier in the path are all stale or near-tie at best.
- **Capacity tuning is asymmetric and now largely resolved.** `K_SITE=6` beats both `5` and `7`, while species-bank changes (`K_SPECIES=7/9/10`) all fail. The useful capacity signal is specifically “smaller site bank,” not “different prototype counts everywhere.”
- **Several tempting branches are now effectively pruned.** Treat these as stale unless new evidence appears: direct forward-pass use of static affinity `A(s,l)`, multiplicative FiLM replacement of the additive cross-attention residual, low-rank site-conditioned species-temperature modulation, feeding `site_head.W_K(M_site)` into cross-attention, query-side raw site residuals, strong-stream mixup, faster Platt calibration, uniform weak-focal rescaling / extra weak-label smoothing, compressed mapped-Perch residuals, and extra global regularization knobs like nonzero weight decay or lower `attn_dropout`.
- **Pre-peak unsupervised/site pressure is still dead on this proxy.** Even after the newer `K_SITE=6` / stronger-anchor / faster-blend retune, turning on unlabeled/site losses before the selected checkpoint still hurts. Post-300 freeze plus phase-2 unsup remained inert. If the thesis’s unlabeled stream is going to matter, it likely needs a different selection protocol or a different objective family rather than more warmup tinkering.
- **Most promising next moves are protocol-repair or robustness moves, not old single-seed knob search.** In rough priority order: (1) continue refining the repaired benchmark cautiously, especially around checkpoint-selection protocol if gains remain above the noise floor; (2) periodically audit promising local incumbents on S22/LOSO so proxy drift is caught early; (3) if architecture is revisited, prefer genuinely new thesis-aligned objectives (e.g. recording-level positives or other ways to use unlabeled/site structure) over more fallback/trust micro-elaboration; (4) if data protocol is revisited, prefer benchmark designs that average over subset draws rather than leaning harder on one special focal subset.
