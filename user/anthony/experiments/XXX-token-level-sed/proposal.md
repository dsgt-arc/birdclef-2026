# Proposal: Token-Level Sound Event Detection with SSAMBA

**Status**: proposed
**Created**: 2026-02-08
**Author**: Anthony

## Hypothesis

Reformulating BirdCLEF training as token-level Sound Event Detection (SED) — where each 10ms token receives a binary species label derived from BirdSet's `detected_events` — will substantially outperform clip-level classification on soundscape validation, because:

1. It provides dense supervision (3000 labels per 30s sample vs 1), allowing the model to learn temporal boundaries of vocalizations.
2. It introduces natural negatives at the token level (most tokens in a recording are silence/background), resolving the zero-negatives problem that plagues clip-level training.
3. Mamba's sequential processing is well-suited for detecting event onset/offset patterns.

## Background

Experiment 006 trains SSAMBA on BirdSet HSN with 30s sliding windows and clip-level multi-label classification. Every chunk inherits the recording-level positive label, producing zero negative training examples. Validation data (soundscape test_5s) is ~55% empty, causing a severe train/val distribution mismatch. After 15 epochs, best val/cmAP is only 0.059.

BirdSet provides `detected_events` annotations generated by [bambird](../../docs/vendor/bambird-scikit-maad.md) — an unsupervised signal-processing pipeline that identifies temporal regions containing bird vocalizations. These are `[start_s, end_s]` pairs with DBSCAN cluster IDs.

With SSAMBA's `patch_size=[128,1]`, each token corresponds to exactly one spectrogram frame = 10ms. This 1:1 mapping means we can directly assign per-token labels from `detected_events` timestamps without any temporal alignment ambiguity.

See: [Unsupervised Event Detection for Per-Chunk Labeling](../../docs/concepts/unsupervised-event-detection-labeling.md)

## Method

### Approach

Replace the clip-level classification head (masked mean pool → Linear → `(B, num_classes)`) with a per-token classification head (Linear applied at each position → `(B, T, num_classes)`). Train with per-token BCE loss using labels derived from `detected_events`. At inference, aggregate per-token predictions within 5s windows for BirdCLEF submission format.

### Architecture

```
Current (exp 006):
  backbone → all_tokens (B, 3001, D) → remove CLS → masked mean pool → (B, D) → head → (B, C)

Proposed (exp 007):
  backbone → all_tokens (B, 3001, D) → remove CLS → (B, 3000, D) → head → (B, 3000, C)
                                                                      ↑
                                                              Linear(D, C) per token
```

### Label Construction

For each 30s training chunk:
1. Look up `detected_events` for the source recording
2. Filter to events from the dominant cluster (`event_cluster != -1`)
3. For each token position `t` (0..2999), corresponding to time `t * 0.01s`:
   - If any detected event `[start, end]` overlaps this frame → label = 1 for the recording's species
   - Otherwise → label = 0
4. Result: `token_labels` shape `(3000, num_classes)`, mostly zeros with 1s at vocalization frames

### Loss

Per-token BCE with logits, masked to exclude padded tokens:

```python
# logits: (B, T, C), token_labels: (B, T, C), padding_mask: (B, T)
loss = F.binary_cross_entropy_with_logits(logits, token_labels, reduction='none')  # (B, T, C)
loss = loss * padding_mask.unsqueeze(-1)  # zero out padded positions
loss = loss.sum() / (padding_mask.sum() * num_classes)  # normalize by real tokens
```

### Inference Aggregation

For BirdCLEF evaluation (per-5s-segment predictions):
1. Predict per-token logits: `(B, 3000, C)`
2. Apply sigmoid: `(B, 3000, C)`
3. Aggregate within 5s windows (500 tokens each): max-pool or mean
4. Output: `(B, 6, C)` for 6 non-overlapping 5s segments per 30s

For BirdSet HSN validation (per-clip 5s predictions):
- Process 5s clip (500 real tokens + 2500 padded) → aggregate 500 real token predictions

### Setup

| Component | Details |
|-----------|---------|
| Data | BirdSet HSN: train split with `detected_events`, val on test_5s. Same mel cache from exp 006 for spectrograms, but need new cache with per-token labels |
| Compute | 1x RTX 6000 (24GB). Similar VRAM to exp 006 — output head is tiny compared to backbone |
| Dependencies | Same as exp 006: ssamba_hf, pytorch_lightning, torchaudio, soundfile |
| Code | Fork from `006-ssamba-birdset-hsn/`, modify classifier, lightning module, data pipeline |

### Procedure

1. Extend data pipeline to extract `detected_events` from BirdSet HF dataset and convert to per-token labels during collation (or precompute into the mel cache)
2. Create `SSAMBATokenClassifier` — same backbone, per-token Linear head instead of pooled head
3. Update lightning module for per-token loss, per-token metrics, and inference aggregation
4. Decide on val evaluation: aggregate token predictions to clip-level for cmAP comparison with exp 006
5. Fast-dev-run to verify shapes, loss, no OOM
6. Full training run, compare against exp 006 baseline

### Variables

- **Independent**: Task formulation (clip-level classification vs token-level SED)
- **Dependent**: val/cmAP, val/AUROC, val/F1 (clip-level, aggregated from token predictions for fair comparison)
- **Controlled**: Backbone architecture (SSAMBA 192-dim, 24-layer), data (BirdSet HSN), training hyperparameters (lr, schedule, augmentation), mel spectrogram parameters

## Evaluation

### Metrics

| Metric | Description |
|--------|-------------|
| val/cmAP (clip) | Class-mean average precision on val clips, aggregated from token predictions. Primary metric, directly comparable to exp 006 |
| val/AUROC (clip) | Area under ROC curve on val clips |
| val/F1_macro (clip) | Macro-averaged F1 on val clips |
| token/precision | Precision of per-token event detection on train set (sanity check) |
| token/recall | Recall of per-token event detection on train set (sanity check) |
| train/loss | Per-token BCE loss (not directly comparable to exp 006's clip-level loss) |

### Baseline

Experiment 006 (clip-level, 30s windows, recording-level labels):
- val/cmAP: **0.059** (epoch 15, early stopped at 30)
- val/AUROC: ~0.53
- val/F1_macro: ~0.03
- Training still running as of 2026-02-08 (may update)

### Success Criteria

- **Confirm if**: val/cmAP > 0.12 (2x improvement over exp 006 baseline of 0.059), indicating that dense token-level supervision with natural negatives meaningfully improves classification
- **Reject if**: val/cmAP < 0.08, indicating that token-level SED doesn't help enough over clip-level, or that bambird event labels are too noisy for token-level supervision

## Limitations

- **bambird event quality**: Events are unsupervised detections, not ground truth. Some vocalizations may be missed (false negatives in labels), and some noise may be labeled as events (false positives). Token-level labels inherit this noise.
- **Cluster filtering**: Using only the dominant DBSCAN cluster assumes the target species is the loudest/most frequent sound. Quiet species or noisy recordings may have poor event detection.
- **Val evaluation gap**: Validation clips (5s soundscape segments) don't have `detected_events` — we can only evaluate at clip level, aggregated from token predictions. We can't measure token-level SED quality on val data.
- **Label sparsity**: Most tokens will be negative (bird vocalizations are sparse in time). May need class weighting or focal loss to handle the extreme imbalance.
- **Single dataset**: BirdSet HSN has only 21 species. Results may not generalize to the full BirdCLEF species set (150+). However, this experiment tests the formulation, not the scale.
- **BirdCLEF generalization**: BirdSet provides `detected_events` out of the box. For actual BirdCLEF competition data, we'd need to run bambird ourselves. This experiment validates whether the approach is worth that effort.
