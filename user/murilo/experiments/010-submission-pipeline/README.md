# Experiment 010: BirdCLEF 2026 Submission Pipeline

Submit LoRA fine-tuned models (EAT, ConvNeXt, ProtoCLR) to the **BirdCLEF 2026** competition via ONNX export and a unified Kaggle CPU kernel. Supports models trained on both BirdCLEF 2025 and 2026 data.

## How It Works

```
Checkpoint (.ckpt)          ONNX model + configs          Kaggle kernel
 LoRA encoder + head   -->  model.onnx                -->  load ONNX
                            species_list.json              compute mel (model-specific)
                            mel_config.json                infer 5s windows
                            species_mapping.json           map probs -> 234 columns
```

1. **Export**: Load Lightning checkpoint, merge LoRA weights into the base model, wrap encoder+head into a single module, export to ONNX (opset 17). Each model's mel preprocessing params are saved to `mel_config.json`.

2. **Species mapping**: `species_mapping.json` maps model output indices to 2026 submission columns. For 2025-trained models: 41/206 map. For 2026-trained models: 206/206 map. Unmapped species default to probability 0.0.

3. **Kaggle inference**: A single `submission.py` kernel auto-detects the model type from `mel_config.json` and dispatches to the correct preprocessing:
   - **EAT** (`kaldi_fbank`): torchaudio Kaldi fbank, 16kHz, 512 frames, AudioSet normalization
   - **ConvNeXt** (`mel`): librosa log-mel, 32kHz, 500 frames, AudioSet normalization
   - **ProtoCLR** (`protoclr_mel`): librosa mel -> dB -> per-sample min-max -> ProtoCLR standardization, 16kHz, 250 frames

## Quickstart

All commands assume you are in the experiment directory:

```bash
cd user/murilo/experiments/010-submission-pipeline
```

### Step 1: Export models to ONNX (GPU required)

The export job builds each model from its checkpoint, merges LoRA adapters, and traces to ONNX. It also builds the species mapping.

Model naming: `{encoder}-{year}[-{variant}]`

```bash
# 2025-trained (exps 006/007/009)
bash sbatch/run.sh export --model protoclr-2025   # single model
bash sbatch/run.sh export --model all-2025        # all 3

# 2026-trained, 80/10/10 split (exp 011)
bash sbatch/run.sh export --model protoclr-2026   # single model
bash sbatch/run.sh export --model all-2026        # all 3

# 2026-trained, 100% fulldata (exp 011 --train-all)
bash sbatch/run.sh export --model protoclr-2026-fulldata  # single model
bash sbatch/run.sh export --model all-2026-fulldata       # all 3

# Preview without submitting
bash sbatch/run.sh export --model protoclr-2026-fulldata --dry-run
```

Logs go to `logs/slurm_export_<model>_<jobid>.log`.

Each export script:
- Reconstructs the encoder + LoRA + head from the config
- Loads the Lightning checkpoint
- Merges LoRA into base weights (`merge_and_unload()`)
- Wraps in a thin `nn.Module` that takes mel input and outputs logits
- Exports to ONNX and verifies output matches PyTorch (atol < 1e-4)
- Saves `model.onnx`, `species_list.json`, `mel_config.json`

ProtoCLR has a TorchScript fallback if CvT's internal `einops` ops fail ONNX tracing.

### Step 2: Validate locally (CPU)

Runs inference on a subset of BirdCLEF 2026 train soundscapes and extrapolates timing to the full ~600 test files.

```bash
# Via SLURM
bash sbatch/run.sh validate --model all-2026
bash sbatch/run.sh validate --model protoclr-2026-fulldata

# Or interactively
python scripts/local_validate.py --model eat-2025 --max-files 10
python scripts/local_validate.py --model protoclr-2026-fulldata --max-files 10
```

Logs go to `logs/slurm_validate_<model>_<jobid>.log`.

### Step 3: Upload weights dataset to Kaggle

Requires `~/.kaggle/kaggle.json` to be configured.

The weights dataset **must exist on Kaggle** before the kernel can reference it. For new models (first submission), always upload the dataset first and wait for it to be available before pushing the kernel.

```bash
# Upload weights dataset only
python scripts/upload_kaggle.py --model protoclr-2026-fulldata

# Upload all fulldata model weights
python scripts/upload_kaggle.py --model all-2026-fulldata

# Dry run (preview without uploading)
python scripts/upload_kaggle.py --model protoclr-2026-fulldata --dry-run
```

### Step 4: Push kernel and submit

Once the weights dataset is available on Kaggle, push the submission kernel. The kernel auto-detects which model weights are attached and runs inference.

```bash
# Upload weights + push kernel (works if dataset already exists)
python scripts/upload_kaggle.py --model protoclr-2026-fulldata --push-kernel

# Upload all fulldata models + push kernels
python scripts/upload_kaggle.py --model all-2026-fulldata --push-kernel
```

> **Note**: `--push-kernel` uploads the dataset then pushes the kernel in sequence.
> For a brand-new dataset that doesn't exist on Kaggle yet, Kaggle may need a few
> minutes to process it. If the kernel fails with "No model weights found", wait
> and re-push the kernel: run step 3 first, wait, then step 4.

**Naming convention** (`{encoder}` = eat, convnext, protoclr):
- 2025-trained datasets: `birdclef-2025-{encoder}-weights`
- 2026 80/10/10 datasets: `birdclef-2026-{encoder}-weights`
- 2026 fulldata datasets: `birdclef-2026-{encoder}-fulldata-weights`
- 2026 80/10/10 kernels: `birdclef-2026-{encoder}-baseline`
- 2026 fulldata kernels: `birdclef-2026-{encoder}-fulldata`

## Known Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| EAT ONNX export fails | Can't submit EAT | EAT uses HuggingFace custom code for `extract_features()`. Fallback: TorchScript or bundle PyTorch model for Kaggle (torchaudio + transformers are pre-installed). |
| ProtoCLR ONNX export fails | Can't submit ProtoCLR | CvT may use `einops` internally. `export_protoclr.py` auto-falls back to TorchScript if ONNX tracing fails. |
| EAT inference too slow | Exceeds 90-min limit | ~90M param ViT on CPU could be slow. `local_validate.py` estimates timing. If >70min projected, try float16 quantization or skip EAT. |
| Mel preprocessing mismatch | Incorrect predictions | Training used nnAudio/torchaudio; inference uses librosa. Each export script verifies ONNX output matches PyTorch reference within atol=1e-4. |
